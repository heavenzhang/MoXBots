## 评审必须覆盖的行为

| 输入/故障 | 应得到的结果 | 不能混淆的边界 |
|---|---|---|
| 纯问答 | 直接答复，必要只读查询 | 不把问句强行转成建站/业务写入 |
| 清楚的行动请求 | 形成明确目标与验收条件后直接推进 | 授权已足够时不机械要求再点确认 |
| 仅请求方案/讨论 | 给方案供审阅 | 不启动生产动作 |
| 多个可独立工作包 | 基于依赖/文件owner/成本决定并行 | 多agent不是每次强制开满 |
| 首个协调模型无输出就失败 | 执行层保留意图，用同一策略换兼容候选 | 不能等故障模型先写出委派指令 |
| 分类模型不可用 | 有界、可解释的保守决策 | 无限制重试/任意升档/额外付费不是默认 |
| 所有兼容候选不可用 | 有界冷却与清楚停因/恢复条件 | 计数增加不代表任务推进 |
| 子agent自报完成 | 证据检查及主Agent验收/返工 | 自报成功不是整体完成 |
| 工具报错/参数错 | 修正工具或任务路径 | 不盲目换模型掩盖权限/逻辑错误 |
| 真实写入结果未知 | 原owner只读核对，不能确认则停 | 不能重放未知业务动作 |
| Stop/撤销/待审批 | 所有相关owner停/等待 | 不用另模型/另线程绕过 |
| App重启/会话恢复 | 依据持久进度/尝试/动作证据续接 | 不从聊天最后一句猜测或重放任务 |
| 完成 | 验收证据对应真实产物/部署/用户路径 | HTTP200、工具返回、模型final都不是通用完成证明 |
