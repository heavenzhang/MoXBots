## Reproduce

From the repository root on the acceptance Mac:

```sh
DEVELOPER_DIR=/Library/Developer/CommandLineTools /Applications/MoXBots.app/Contents/Resources/nodejs/bin/node --import tsx scripts/verify-mobile-original-host-interactions.ts
```

The script creates an empty 0700 temporary HOME/workspace, uses the original
local operator fixture to configure a 127.0.0.1 synthetic provider and ordinary
registered Agent, stores a generated runtime-only credential through the original
encrypted credential owner, bundles the actual main/worker, and uses the actual
installed SDK0.3.296/native child. Actual private Unix IPC controls the original
Session owner. No pending request, Session metadata, tool result, terminal event,
ToolAttachment or source pointer is written by the fixture.

The synthetic supplier emits actual Anthropic tool_use SSE. The SDK itself
invokes Bash and Read through original custom-mode policy (`SDK default`), with
original canUseTool/hard hooks intact. Fixture commands write only the private
workspace. Approval is original remote `respond` with allow_once/deny;
no fullAgency, session grant, disabled hook or helper approval bypass is used.

Original entry points inspected before implementation:

- worker remote respond/stop validates exact generation/engine turn; respond
  refreshes original `buildRemoteSnapshot` and checks matching request and
  actionable review before calling the engine permission owner.
- `checkToolPermission` owns the real pending map; `projectRemoteInteractions`
  limits complete permission reviews to less than500 characters. Fixture Bash
  input is required to fit that existing boundary, not truncate around it.
- `attachBuiltinMediaIfAny` handles real SDK image tool_result output through
  original ToolAttachment writer. Artifact owner projects persisted assistant
  tool attachments, then binds exact bytes/inode/mtime/hash for list/read.
  Plain Write text is not automatically an output artifact.

1. Real native Bash requested permission to create a PNG. Fresh original

   snapshot still contained the real pending request. Exact matching explicit
   denial completed the turn without creating the file.
3. A second mobile send caused a new real Bash pending request. After another
   fresh snapshot, exact-generation approval let actual Bash execute fixed Node
   code to create a known68-byte PNG in the private workspace. The supplier then
   requested actual native Read of that file. The original image tool-result
   pipeline persisted the ToolAttachment; owner list returned exactly one source,
   and owner read returned the generated bytes and exact hash:
   `5e3d382db4dd83d59aa5742793ad6b7903409e865c83bcbc54835049f043bc15`.
4. Reusing the settled approval with a new mutation ID was rejected as expired,
   without a supplier call. A third real pending write was stopped through the
   exact generation/turn owner; terminal became stopped. A later approval of its
   old request was rejected and its target file never existed. Supplier calls
   stayed6 (two for deny, three for approved Bash+Read, one before Stop).

First actual run was GREEN4797ms at private fixture
`.mox-host-interactions-2rdN2T`. Independent fixture-data inspection then found

and the final run above uses the corrected sample. No production change was
