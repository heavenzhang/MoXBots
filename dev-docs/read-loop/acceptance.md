## 根因判定

观察证据（`salary-read-loop-evidence.json`、`latest-snapshot.json`）：

- 单个长轮次 94 个工具调用，编辑/写入工具 0 个；同轮次内同一业务服务实现文件被读取 24 次，另有多个文件重复读取。
- 证据中精确命令哈希重复数为 0：未发现客户端重放已交付工具、未发现 bridge 截断历史。
- 同一文件的连续 4 次 `Read` 出现在 10:52、11:15、11:38、12:02 四组，后三组紧跟在 SDK 自动压缩（10:49、11:13、11:36、12:00）之后；模型在压缩丢失上下文后重新读取已读内容。
- 因此判定为**模型行为不收敛 + 自动压缩放大的重复阅读**，不是客户端重放缺陷。未虚构"历史被清空/重放"类修复。
- 客户端侧可改进点：现有进展投影（`src/shared/sessionWorkProgress.ts`）只服务 UI，不向模型反馈"已读内容重复、仍未产生产物"。

## 实现

新增 `src/server/builtin-session/progress-convergence.ts`（叶子模块，不依赖运行时）：

- 每轮维护已读区间账本（跨阶段声明**不清理**，以便识别压缩后的重复阅读）；按文件记录重叠重读计数（每次阶段表态后重置）。
- 只有同时满足以下条件才发提示：存在阶段表态或用户执行意图；连续只读工具 ≥4；重叠重读 ≥2 次且集中在同一文件；本轮编辑/写入为 0；距最近一次验证命令 ≥4 个操作；不在等待用户；不是只读/研究型任务。
- 每次阶段表态最多提示一次，每轮最多 3 次；提示文本不含路径、文件内容、会话 ID。
- 顺序分块读取（1-2000、2001-4000…）不构成重叠，不会触发。

接线：

- `src/server/builtin-session/turn.ts`：轮次边界（`setCurrentTurnSourceItem`、`resetTurnUsage`、`resetTurnForTest`）重置账本；`appendCurrentTurnTextBlock` 把可见助手文本送入阶段扫描。
- `src/server/agent-session.ts`：`PostToolUse` 观察工具并注入 `additionalContext`；`switchToSession` 重置进程级账本，避免跨会话继承；日志仅输出脱敏计数。

## 测试（原问题与反例）

`src/server/builtin-session/progress-convergence.unit.test.ts`，13 个用例：

原问题复现（通用模式，不硬编码会话 ID / 94 次）：

1. 阶段表态 + 同一文件重叠重读 ×4 + 0 编辑 → 第 4 次读取产生提示。
2. 同一阶段不重复提示；新表态后才允许再次提示；每轮上限 3 次。
3. 压缩后重新读取**上一阶段已读区间**（新表态 + 4 次同区间重读）→ 产生提示。

反例（不得误报）：

- 显式只读/分析/审查任务，即使模型说"开始修改"也不提示。
- 大文件顺序分块读取不提示；单个冗余重读不提示，第二个才提示。
- 验证/构建命令后立即的 3 次读取不提示。
- 已产生任何编辑/写入后不再提示。
- `AskUserQuestion` 等待用户后不提示。
- 子代理（`agent_id` 存在）的工具不进入主轮账本。
- 无阶段表态且用户消息无执行意图时，30 次重叠读取也不提示。
- 英文否定句 "I will not start editing yet" 不计为新阶段。
- 提示文本不含路径、文件名、会话 ID。
