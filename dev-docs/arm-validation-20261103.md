# 共享 CI ARM 原生检查：受限的本机补证

## 原则与适用范围

本流程仅用于本仓库共享 CI 的同一 macOS ARM 原生检查及其完整 12 项清单，不因候选部署单元而改变检查内容；包括需经过该检查的桌面、手机和 Host 源码候选。不得用本补证替代其他平台或其他检查。它不改变产品的 Xcode 26+ 最低构建要求、原生检查内容、发布凭据权限或业务验收。原托管配置仍为 macOS 15 ARM、Xcode 26.3、三套 SDK 26.2；所有原断言和产品步骤保留。`07f31b66234e682e435ea2188df51e7edb83ea87` 记录该镜像选择是为了当时托管执行器不可用时保留原生检查；本机签名环境独立。参见 `specs/guides/macos_distribution_guide.md` 与 `specs/guides/build_and_release_guide.md` 的目标平台和本机真实测试要求。

## 两套精确环境

- `hosted-macos15-arm`：ARM、Xcode 26.3、macOS/iPhoneOS/模拟器 SDK 均 26.2、Node 24、Rust 1.92.0、aarch64-apple-darwin。
- `local-macos-arm-27.1`：ARM、Xcode 27.1 build 27A9275、macOS SDK 27.0、iPhoneOS 和模拟器 SDK 27.1、Node 24、Rust 1.92.0、aarch64-apple-darwin。仅支持这组实际核验过的版本，不泛化到其他 SDK 或 Intel。

`scripts/arm-validation-contract.mjs` 校验源码提交、树、干净状态与五个锁文件摘要，精确环境和完整托管检查清单。`scripts/run-local-arm-validation.mjs` 对精确源码运行同一产品检查清单，每步单独保存退出码和日志摘要；不得使用用户业务目录、会话、生产钥匙串或历史账本。仅允许脚本创建的指定零字节普通占位文件；其他未提交文件、源码或锁文件变化均拒绝。

## 候选准入条件

唯一共享 CI 负责人可以在以下条件全部满足时，将本机结果作为**该候选、该本机环境的 ARM 原生补充准入**，并邀请独立审阅；各端正式构建、签名、安装和发布仍由相应部署单元负责人执行：

1. 目标托管 ARM 项目的原始结果证明未取得执行器且零步骤执行，且有实际容量/未分配执行器证据；没有任何实际执行的产品检查失败。保留全部尝试及注释，不把取消写成通过。
2. 同一最终候选 SHA、整树和相关锁文件与其他全部适用 CI 结果匹配并通过；仅条件不适用的项目可如实标记跳过。若源码、锁、候选或检查命令发生变化，重新验证受影响证据。
3. 本机按精确 `local-macos-arm-27.1` 执行完整 12 项产品清单，全部退出码为 0；源码和锁文件检查在前后通过，日志与摘要完整可复核。保留 GitHub 托管取消、本机环境差异和原始日志。
4. 发布负责人写入引用具体来源及结果的准入记录，独立审阅者检查环境、清单、源身份、结果和失败边界；任何缺失、未知、实际测试失败或身份不一致均不得准入。

本机通过是独立的本机 ARM 验证结果，**不是 GitHub CI 通过**，也不证明托管 SDK 26.2 上本次检查成功。源码合入仍须遵守实际分支保护和审查；签名、公证、安装、原生用户路径和正式渠道各自验收。手机候选的本机检查不证明手机安装、签名、真机业务或 TestFlight 已通过；Host 源码候选的本机检查不证明 Linux 制品、部署或实际 Host 链路已通过。原恢复业务和 stable 渠道门禁不因导航验收或此补证自动解除。
