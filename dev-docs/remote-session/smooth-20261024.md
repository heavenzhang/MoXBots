# 远程会话流畅展示修改方案与执行记录

任务：`REMOTE-UI-SMOOTH-20261024`，接续 `REMOTE-UI-20261020`。

## 目标与判断

用户希望远程会话在技术架构、内容展示和使用手感上与本地会话统一。现有远程页面已经复用普通会话的 `MessageList / Message / BlockGroup / ToolUse` 和滚动控制器；本次继续沿这条路径优化输出更新，避免另建一套远程聊天渲染器。

源码核查发现：前台执行中会话仍在每次读取完成后固定等待 1500ms；新解析的快照即使内容不变，也会重建消息数组或工具展示块；每次成功读取还会广播侧栏观察状态。这些行为会增加输出等待和前端更新工作。它们是可由源码与本地测试确认的改进点；真实双端的网络耗时、刷新性能和使用效果仍需发布后验证。

## 修改方案

| 改进项 | 执行方式与代码位置 | 完成标准 |
| --- | --- | --- |
| 执行时更快获取输出 | `useRemoteSessionPolling.ts`：前台可见且实际状态为 running 时，下一次读取在上次完成后等待 300ms；idle/waiting/terminal 为 1500ms，后台或隐藏为 5000ms | 运行、空闲和后台分别按对应节奏读取；慢请求期间不重叠；唤醒合并 |
| 失败时控制读取负载 | 同一轮询循环按连续读取失败使用 1.5/3/6/12/15s 退避，后台最低 5s；成功后恢复状态对应节奏 | 不形成失败密集重试；聚焦、激活、显式刷新沿原入口唤醒 |
| 未变化内容保持稳定 | `RemoteSession.tsx` 的 `adoptSnapshot` 与 `transcriptPresentation.ts` 的 `reconcileRemoteMessages` 复用既有 `shareEqualJson`，保留未变消息数组、消息和工具记录的引用 | 相同快照不改变时间线输入；真实文本和工具结果变化仍正常展示；generation 变化重新建立展示范围 |
| 减少工具块重复计算 | `presentRemoteTranscript` 缓存未变工具的展示块，并绑定所属 message ID | 正文增长时已完成工具块保持稳定；工具结果变化会替换；跨消息共用 raw tool 时不混用 block ID |
| 减少全局广播 | `RemoteSession.tsx` 的 `reportObservation` 按界面已采用的分钟精度比较成功同步时间；标题、状态、同步错误和未读变化即时发布 | 同分钟内无变化读取不广播 App 侧栏；保留一次真实成功读取的时间，不伪造同步状态 |
| 保持本地会话交互 | 继续使用既有消息组件、虚拟列表和滚动 owner，不另建布局或滚动状态 | 轮询后草稿与工具折叠保持；加载旧页及新增输出不抢走阅读位置；窄窗可用；发送一次只提交一次 |

300ms 是读取完成后的固定等待，较原等待减少 1200ms；它不包含远端处理和网络往返，不能解释为真实端到端延迟承诺。运行中读取次数会增加，后台降频、失败退避和串行读取用于约束影响；真实负载尚待双端验证。

现有能力提供有界快照，`session.watch` 也不是持续聊天事件流。本批使用现有请求路径，不增加 SSE/新协议、模拟逐字输出或第二个执行/持久化 owner。没有数据库、配置或依赖迁移。账号、设备、generation、操作回执、审批、IME/草稿和更新准入继续由原有入口裁决；未确认操作只查回执，不能自动重发。
