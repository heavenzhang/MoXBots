# Builtin API context recovery

Owner: existing builtin Query token, bridge, SessionStore and Rust SessionGoalManager. Task: MOXBOTS-CONTEXT-RECOVERY-20261017.

## Capacity and compaction

An API provider's model `contextLength` is declared capacity, not evidence that every upstream route accepts that size. Non-managed third-party API-key routes default to a 200,000-token operational compaction budget, capped by a smaller declared window. A model row's explicit `contextCompactionWindow` can raise/lower this budget; it never raises declared capacity. Native model aliases still derive `[1m]` from declared capability. The SDK compaction window and UI denominator share the operational policy. The UI identifies operational budgets separately. Official Anthropic, subscription/managed endpoint and cloud-scoped authority retain their existing policy.

## Inference-only repair

Only explicit context-overflow responses (400/413/422) trigger one reduced inference retry. Generic HTTP400 pauses the Goal as an invalid request. Before retry, SessionStore commits the complete request into a private, content-addressed, immutable archive. Reduction preserves every system instruction, user text, tool name/input/ID, paired result ID and latest two messages. Only older bulky assistant text/tool evidence is excerpted with archive references and hashes. Internal SDK system messages are preserved. Unknown block shapes, missing/uncertain tool pairs, inadequate reduction, background work, concurrent inference, stale tokens and cancellation stop automatic repair. Native histories are never rewritten and queue turns are never replayed.

SSE delivery remains admitted until message_stop. Partial streams seal the request against implicit replay. Native /compact success creates the SDK's own compact_boundary. Its explicit compact_result=failed overrides an outer SDK success result. Structured failure codes pass through the JS terminal outcome to Rust; Rust pauses the same Goal, preserving objective/progress and explicit resume, instead of ten identical retries ending in a terminal blocked Goal.

## Action protection and persistence

Once repair is armed, a Query-level ledger keys business actions by tool name plus canonical JSON input, independently of native tool IDs. Known successful actions are denied with prior evidence; Read/Grep/Glob remain repeatable. Every newly allowed business action first reserves an uncertain entry durably, then commits success from PostToolUse. A crash or failure between these commits leaves an uncertain action that must be checked read-only before further automatic execution. Ledger commits serialize within the controller and validate the current Product/native-history owner in SessionStore. A new Query restores the same-history ledger, including after native compaction has removed old tool pairs. Corruption, write failure and ledger capacity exhaustion fail closed. An immutable same-history armed marker also makes a missing ledger fail closed.

Private files: `<app-data>/context-recovery/<product-session>/`: SHA256 request JSON and `ledger-<native-session>.json`, directory0700/files0600. Ledger<=16MiB/2048 distinct actions; immutable archives<=128 and256MiB total, each<=64MiB. Limits stop automatic recovery without deleting evidence. Existing Product/native transcripts remain authoritative; archives are operational evidence, never source-controlled. Different native histories use distinct ledgers.

This is exact tool/input replay protection, not distributed exactly-once delivery: semantically equivalent operations with changed arguments require business-system idempotency keys and receipts. A tool must report its real success/failure; an ambiguous result is never proof of success. Downgrading to an older binary that lacks these gates requires pausing affected Goals and preserving/exporting their checkpoints first. Do not let the old version automatically continue recovered business work.

## Settled background stream continuation

Task MOXBOTS-SETTLED-STREAM-CONTINUE-20261021 adds a narrow result-boundary path through the existing SameTurnStreamContinuation and SessionModelRecovery. It neither replays an HTTP request nor creates another queue, waiter, recovery owner or budget. The original root/native Session/route/Goal remain unchanged; a one-use marker in the last native user input retires all old-root fingerprints and opens a distinct inference namespace. Completed action hashes remain denied.

Admission requires the original live Query, an armed clean durable ledger, no active request, a stable manifest of every admitted request in that scope, and zero tool bytes possibly delivered by every interrupted request. Delivery evidence is recorded before enqueue: malformed/unknown SSE, prefilled message content, orphan argument deltas, conflicting indices/IDs, unfinished or invalid arguments cannot grant a receipt. Tools from completed streams must match exact native tool IDs and canonical action hashes at PreToolUse and have paired PostToolUse/Failure terminals. All known background runs (including level-only observations) must have exact run identity and authoritative task_updated terminal evidence; a notification, user ACK, disappearing level or cleanup never substitutes. Current nonambient level must be empty. First version conservatively requires terminal evidence for all known task edges, so ambiguous/ambient edges without a provable run may also deny this path.

Transport cause is an internal request/attempt-local callback from the original body/timeout owner, never an HTTP header, model error string or generic rewritten SSE frame. Provider/auth/billing/policy errors, parse failures and Abort/consumer cancellation cannot arm either the new receipt or the existing foreground continuation. Raw Anthropic clean EOF without terminal and real socket/body-idle failure retain their explicit cause; Chat/Responses clean EOF requires a validated model-progress prefix and no incomplete SSE frame; parser/provider errors, ping-only and half-frame EOF remain unproven. Callback revocation follows the existing attempt and request lifecycle.

Only background work already settled when the original native result arrives is supported. If it settles later, the result is finalized under the existing protection; no hidden polling/held result is added. Terminal HTTP rejections are outside this narrow stream receipt path; an unrelated authentication/policy failure is not promoted into retry authority. Historical unknown actions, capacity exhaustion, stale manifests, Stop, owner/route changes or failed storage/CAS remain blocked, with a fixed non-secret explanation in the original conversation. Evidence is bounded independently: 4096 request/tool-delivery entries and background run observations, native action/admission evidence limited to the existing 2048-entry ledger bound, argument witness at most 1MiB. Capacity disables this new proof without evicting old safety evidence or changing ordinary tool permission.

Receipts use the existing immutable SessionStore archive writer with SHA256 of its exact JSON bytes; ledger and checkpoint writes retain the same owner and durable CAS. New checkpoints are version2/kind=stream and carry the receipt digest plus original engine authority. This proof is live-only: cold Session restoration, Goal request admission or another engine cannot reconstruct permission from a ledger/archive alone and must pause. v1 checkpoints without this proof retain their previous behavior; v2 never downgrades during wait/rebind/pause. The original consumed receipt can authorize subsequent interruptions of the same live chain while preserving its id and earliest deadline. Older 5158/e7 readers reject version2 rather than treating it as a normal waiting checkpoint during rollback. This is controlled refusal after restart, not automatic cold recovery.

Synthetic tests cover the real handler with both controllers, actual SessionStore file publication, two same-id/same-deadline namespace continuations, native SDK result/Pre/Post hook wiring, Stop across commit/adoption, Query replacement across the new await, and cold refusal. Real native/provider recovery and original business completion remain separate acceptance.
