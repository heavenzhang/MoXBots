# 目标模式、待办与协作状态栏

本规范约束 Composer 附近的 `ExecutionStatusBar`。视觉 Token、字号、Focus 和通用控件遵循 `../DESIGN.md`。目标执行由 SessionGoal owner 裁决，待办与协作从既有 transcript/runtime 投影；勾选比例不代表目标已完成。

## 统一摘要与详情

- 普通会话执行、运行目标、待办、子 Agent 共用一条无外框的紧凑摘要行，位于 Composer 上方，默认收起；无对应数据不显示摘要，无任何数据不显示状态栏。
- 摘要依次显示普通执行短状态、目标状态及轮次、任务完成数/总数和非零执行数。待验收数作为固定右侧入口，点击直接打开原任务详情，只查看、不触发验收；无任务但有协作时显示“协作”，不显示 0/0。子 Agent 回传不等于主 Agent 验收。异常同时用文字和颜色表达。
- 目标正文、完整终态原因与结算详情进入目标详情；长目标自然换行、可选取，长内容在唯一详情区内滚动。摘要内的长终态说明截断，不持续挤占其他摘要。
- 点击摘要或 Enter/Space 展开对应详情，再点同一摘要收起，点击另一摘要切换；普通执行详情也由同一个 disclosure owner 控制；外部仅一个展开区，最高 `min(280px,38vh)`，子 Agent 嵌入模式不再自设第二层滚动。
- 目标摘要保持共享 TargetIcon；正常运行 Accent、完成 success、受阻 warning、暂停/取消 muted。默认行高为共享 compact-action 的 32px，不使用大背景色或非必要动画。
- 摘要按钮具有 `aria-expanded`、`aria-controls`，详情具有有名称的 region。Escape 从摘要或详情收起并返回相应摘要焦点；输入法合成期间不拦截 Escape。
- 窄窗口只滚动左侧摘要，待验收、暂停/继续与更多动作固定在右侧，状态栏不换行、不造成页面横向溢出。摘要均可滚动或通过键盘访问。

## 目标控制

- 活跃目标（包括轮次间等待）始终外置暂停，暂停后外置继续；均复用原 Rust Goal owner 的停止、持久化和继续入口，每次点击只调用一次原回调。
- 编辑/取消放入共享 DropdownMenu，取消沿用 Chat 既有确认及执行回执；终态关闭也在菜单内。视觉组件不直接写执行状态，不推测成功，不增加执行器。
- 终态保留原目标和结算摘要；结算中只显示汇总中，不能提前展示总耗时或消耗。无回调不呈现可操作假象。
- 草稿目标与定时任务条仍由原组件展示，它们的创建和排队操作不在此次整合范围。

## 待办与协作

- 待办只读，先展示进行中再展示待处理，同组保留源顺序；进行中使用 activeForm（缺失回退 content），不拿待处理项冒充当前工作。
- 已完成项默认在“已完成 N 项”内折叠，展开后可读；不加删除线或可编辑复选框。
- 没有目标/协作维持状态栏时，已完成待办仅在活跃待办结束后驻留一次约 2 秒；仅含已完成待办的空闲历史冷打开保持隐藏，不重复复活。有目标/协作时可持续复查已完成待办计数。
- 子 Agent 详情保留本轮/整个会话切换、更早历史加载、加载失败重试和原 inspector 入口。历史摘要只统计已载入记录。
- 本地后台任务保留原状态/日志对话框与原消息定位入口；日志对话框不因状态摘要结束而自动卸载。
- 会话切换默认收起，旧会话详情和选中后台任务不能泄漏到新会话；进度更新不能自动展开或抢输入焦点。鼠标点击摘要使用共享 retainFocusOnMouseDown 保留 Composer 焦点和草稿；键盘 Enter/Space 仍可展开，Escape 返回实际触发按钮。

普通执行的目标正文、完整原因、执行轮数、验收条件及证据覆盖进入执行详情；意图未确认和同步中的短状态不得冒充执行或验收成功，旧请求结果不能投射到新请求。

## 验收边界

至少覆盖三类摘要同一行、默认收起、互斥展开、已完成项、Escape/IME、后台日志和历史分页、目标暂停/继续/菜单/终态、空数据、会话切换、长目标、320/390/768/桌面与浅深主题。排队消息仍保留独立编辑/取消区域。

可复现合成组件入口与证据见 `../../dev-docs/unified-statusbar/acceptance.md`。签名包、真实账号和原生目标任务验收由唯一桌面发布 owner 在下一未冻结版本单独完成，组件测试不能代替发布验收。
