# 目标模式与待办交互

本规范约束聊天 Composer 附近的 `GoalStatusBar` 与 `AgentStatusPanel`，视觉 Token、字号、Focus 和通用控件遵循 `../DESIGN.md`。执行状态仍由 SessionGoal 与运行时待办事实裁决，界面不推测任务完成或下一步执行状态。

## 信息层级

目标模式回答“本次要完成什么、现在处于什么阶段”；待办回答“已完成多少、正在做什么”。两者独立显示，不把待办勾选比例当作目标完成依据。

- 目标条依附 Composer 上沿，使用中性 `paper-elevated` / `line`，不以大面积危险色表示正常执行。
- 首行用 12px 状态和轮次/终态摘要，第二行用 14px 目标正文。状态文字与旗帜共同表达语义。运行用 Accent、完成用 success、受阻用 warning、暂停或取消用 muted；背景保持中性。
- 目标默认最多两行，右侧箭头提示可展开；原生 disclosure 支持鼠标、Enter/Space，展开后可读取全文，全文区域最高 `min(128px,20vh)` 并可键盘滚动，终态同样保留。设置使用独立按钮，不把轮次与目标混成隐蔽的编辑入口。
- 设置、继续、取消、关闭使用至少 32px 热区，带可见 Focus。取消默认次级文字，hover 可提示危险语义；沿用既有确认和执行回执，不在视觉组件中直接改状态或重复发请求。
- 终态继续展示目标和原始结算摘要；结算未完成时显示汇总中，不提前输出消耗总数。无回调的动作不呈现可操作假象。

## 待办

- 默认收起为至少 40px 的摘要行：本地化待办名称、已完成/总数、小型进度条、真实进行中事项。没有进行中项时不拿待处理项冒充当前工作。
- 摘要常驻卡片顶部，点击或 Enter/Space 展开/收起；展开箭头向上，收起箭头向下。`aria-expanded` / `aria-controls` 关联内容，`aria-describedby` 提供计数及当前事项。
- 展开后先列进行中，再列待处理，各组内保持源顺序。进行中用 Accent 标记、浅底和中等字重，采用运行时 activeForm（缺失则 content）。待处理保留中性标记。
- 已完成项默认折叠在“已完成 N 项”下；展开后仍可读取，使用勾选标记和次级文字，不加删除线。所有待办只读，不以复选框外观暗示用户可修改执行状态。
- 卡片宽度上限 360px，受父容器约束。详情区高度上限为 `min(280px,38vh)`，待办与协作共享一次内部滚动，长中文、代码标识符和路径自然换行。
- Escape 收起详情并返回摘要焦点；输入法合成期间不拦截 Escape。完成态保持既有驻留/淡出生命周期，不因历史回放重复出现，也不因为换版重算执行事实。

## 组合、主题与验收

卡片沿用 Composer 外部 panel 行，与排队消息并排或换行；不增加固定 bottom 偏移，不抢占输入焦点，不以整屏遮罩阻止阅读。浅/深主题均使用语义 Token。减少运动设置下移除非必要淡入淡出动画。

验收至少覆盖：收起→展开→完成项展开→Escape；进行中优先与原始计数一致；无进行中项、完成记录、终态汇总；长目标全文、长代码行和长列表；320px 组件可用宽度与桌面宽度、浅/深主题；设置/继续/取消/关闭每次仅调用既有回调一次；历史完成项冷打开不复活。

可复现合成组件入口与证据边界见 `../../dev-docs/goal-todo-ui/acceptance.md`。签名包、真实账号与原生目标任务验收由唯一桌面发布 owner 在下一未冻结版本单独完成，组件测试不能代替发布验收。
